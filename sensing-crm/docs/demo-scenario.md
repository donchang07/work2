# 데모 시나리오 — 「놓친 이탈 고객, 가람제약을 되찾아라」

> 자동화 → 예측 → 시뮬레이션 → 최적화를 한 고객의 이야기로 잇는 25분 강의 시연
> 기준: Sensing CRM v1.1 시드 데이터(`npm run setup`, 시드 42). 아래 수치는 2026-11-09 리허설 실측값이며, 시드는 실행일 기준 상대 날짜라 다른 날에도 같은 값이 나온다.

---

## 0. 한 줄 메시지

**"AI 모델을 바꾸지 않았다. CRM에 들어온 정보 한 건이 위험 판정과 다음 행동을 바꿨다."**

시드 데이터는 '자동화 50%' 수준의 조직을 재현한다. 정답 이탈 고객 6곳 중 4곳만 고위험으로 잡히고 **가람제약·늘봄제약 2곳은 '중'으로 숨어 있다.** 시연은 그중 가람제약을 자동화로 되찾는 과정이다.

## 1. 4가지 AI 도입 목적과 화면 대응

| 목적 | 시연 화면 | 증명하는 것 | 관찰 지표 |
|---|---|---|---|
| ① 자동화 | 데이터 운영 · 오늘의 브리핑 · 리드 인박스 · 미팅 노트 · 데이터 품질 | 신호 수집·리드 변환·메모 구조화·고객명 통합이 사람 손을 덜고 CRM을 채운다 | 신호·리드 건수, 구조화 7필드, 일관성 지표 |
| ② 예측 | 위험 고객 | 채워진 정보로 이탈 위험 판정이 바뀐다 | 가람제약 **56점 '중' → 61점 '고'** |
| ③ 시뮬레이션 | 품질-성과 실험실 | "자동화 수준이 다르면?"을 같은 정답으로 비교한다 | 재현율 **17% → 100%** |
| ④ 최적화 | 다음 행동 | 한정된 영업 시간을 어디에 먼저 쓸지 우선순위로 정한다 | 가람제약 1순위 **경영진 리뷰 미팅(3일 내 방문)** |

> 정직한 범위 설명(강의 중 한 번 언급): ③은 **데이터 품질 시나리오 시뮬레이션**이다. 가격·경쟁사 생산 같은 사업 시뮬레이션(S-1~S-5)은 이번 데모 범위 밖(PRD NG-03). ④는 고객별 행동 후보를 규칙 기반으로 **우선순위화(상위 3개 선택)** 하는 단계로, 영업 인력 배치 같은 수리 최적화(O-1)는 다음 단계 과제다.

## 3. 시연 대본

### 오프닝 — 문제 제기 (2분) · KAM 창

1. **위험 고객** 메뉴. "고위험 4곳"을 보여 준다.
2. 가람제약(56점, **중**)을 가리키며: *"가람제약은 사실 공급사를 바꾸려는 이탈 고객입니다. 그런데 시스템은 '중'이라고 합니다. 왜 놓쳤을까요?"*
3. **근거 보기** → 경쟁사 언급 1회, 불만·부정 1건. *"현장에서 들은 이야기가 CRM에 다 들어오지 않았기 때문입니다."*

### 1막 — ① 자동화: 정보를 사람 손 없이 모은다 (8분)

**1-1. 시장 신호 수집 (A-1) · 관리자 창**
- **데이터 운영 → 신호 수집 실행**. 토스트: **"신호 10건을 수집했습니다(중복 5건 제외)"**
- 멘트: *"공시·뉴스·임상·국가과제 피드를 매일 사람이 읽는 대신, 수집·중복 제거·고객 연결까지 자동으로 합니다."*

**1-2. 리드 변환 (A-2) · 관리자 창**
- **리드 변환 실행** → **"리드 4건을 만들었습니다"**

**1-3. 오늘의 브리핑 · KAM 창**
- **오늘의 브리핑** 새로고침 → 가람제약 카드 **「가람제약, 원부자재 공급사 재선정 검토」** (경쟁사평가, AI 요약)
- 멘트: *"KAM은 출근하자마자 담당 고객 변화 한 장을 받습니다."*

**1-4. 리드 인박스 · KAM 창**
- '새봄바이오'(후보, 유사도 0.79) → 그냥 **수락** → "매칭할 고객을 선택하세요" 오류
- 멘트: *"AI가 확신하지 못하면 사람에게 넘깁니다. 자동화의 핵심은 사람이 확정하는 지점을 설계하는 것입니다."* → 고객 선택(또는 '신규 고객으로 등록') 후 수락

**1-5. 미팅 노트 (A-5) — 오늘의 핵심 입력 · KAM 창**
- 가람제약 브리핑 카드 → **고객 360 보기** → **미팅 노트 작성** (고객이 미리 선택됨), 미팅일 = 오늘
- 메모 붙여넣기(날짜는 오늘+4일로 수정):

```
구매팀 이 과장 미팅. 오늘 공시된 원부자재 공급사 재선정 건 확인 요청. 관심 제품은 크로마토그래피 레진, 질량분석기. 베타바이오텍 제품과 비교 평가 중이라고 언급함. 납기 지연이 반복되어 불만을 표시함. 전반적으로 반응이 좋지 않았음. 다음 단계: 구매 담당자와 계약 조건을 협의한다. 다음 접촉 2026-11-13 예정.
```

- **AI로 구조화** → 7필드 제안: 니즈 / 제품군(크로마토그래피 레진, 질량분석기) / **경쟁사(베타바이오텍)** / **불만(납기 지연)** / 다음 단계 / 다음 접촉일 / **반응(부정)**
- 니즈를 한 줄 고쳐 "수정됨" 표시를 보여 준 뒤 **확정 저장** → 최근 기록 '확정', 수정 필드 수 1
- 멘트: *"AI가 쓴 값과 사람이 확정한 값을 따로 저장합니다. 이 '수정 필드 수'가 바로 데이터 정확성 지표의 원천입니다."*

**1-6. 고객명 통합 · 관리자 창**
- **데이터 품질** → 6개 지표(종합 약 83%) → 통합 대기열 **"가람제약사" ↔ 가람제약 (유사도 0.96)** → **같은 고객으로 통합**
- 일관성 지표가 오르고 추세 그래프에 점이 하나 늘어난다.
- 멘트: *"'가람제약사'라는 다른 표기 때문에 위협 신호가 고객에 붙지 않았습니다. 고객명 하나가 데이터 품질입니다."*

### 2막 — ② 예측: 같은 모델, 다른 판정 (3분) · KAM 창

1. **위험 고객** → 가람제약 **61점, 고** (시작할 때는 56점, 중)
2. **근거 보기**: 경쟁사 언급 **2회(+13.3)**, 불만·부정 **2건(+15)**, 주문 감소 33%(+23), 위협 신호 2건(+10), 접촉 공백 **0일(+0)**
3. 멘트(핵심):
   - *"방금 미팅을 했으니 접촉 공백 점수는 오히려 8.9점 **줄었습니다.** 그런데도 등급은 '중'에서 '고'로 올랐습니다."*
   - *"모델은 그대로입니다. 바뀐 것은 **CRM에 들어온 정보 한 건**입니다."*

### 3막 — ③ 시뮬레이션: "만약 우리 조직 전체가 그렇다면?" (6분) · 관리자 창

1. **품질-성과 실험실 → 실험 실행**
2. 결과(같은 정답 고객 30곳·이탈 6곳, 같은 규칙):

| 지표 | 자동화 0% | 25% | 50% | 75% | 100% |
|---|---|---|---|---|---|
| 종합 품질 | 69% | 76% | 84% | 89% | 96% |
| **이탈 탐지 재현율** | **17%** | 33% | 67% | 83% | **100%** |
| 정밀도 | 100% | 100% | 100% | 100% | 100% |
| 추천 적중률 | 46% | 54% | 75% | 88% | 100% |

3. 멘트:
   - *"지금 시연 데이터가 자동화 50% 조직입니다. 이탈 고객 6곳 중 4곳만 보였죠. 가람제약은 보이지 않던 2곳 중 하나였습니다."*
   - *"정밀도는 늘 100%입니다. 품질이 낮다고 틀린 경고가 뜨지 않습니다. 그냥 **조용히 놓칩니다.** 그래서 현업은 문제를 못 느낍니다."*
   - *"수기 입력 조직은 이탈 고객 6곳 중 1곳만 봅니다. 자동화 투자의 ROI는 모델이 아니라 여기서 나옵니다."*

### 4막 — ④ 최적화: 그래서 내일 무엇부터 하나 (4분) · KAM 창

1. **다음 행동** → 가람제약 카드:
   - **최우선** 경영진 리뷰 미팅·장기 공급계약 제안 — 방문, **3일 내**
   - 높음 비교 기술자료 전달·기술 세미나 초청 — 이메일, 7일
   - 높음 증설 라인 소모품 공급 제안 — 방문, 7일
2. 멘트: *"2막 전에는 1순위가 '기술자료 이메일'이었습니다. 위험 등급이 바뀌자 '3일 내 경영진 방문'이 맨 위로 올라왔습니다. KAM의 한정된 시간을 어디에 먼저 쓸지 시스템이 정해 줍니다."*
3. **채택** → 채택 탭으로 이동. 다른 추천 하나는 **거절**을 눌러 사유 필수("거절 사유를 선택하세요")를 보여 준다.
4. 멘트: *"채택·거절과 그 사유가 다시 데이터가 됩니다. 다음 추천의 품질을 올리는 피드백 루프입니다."*

### 클로징 (2분)

```
자동화(A) ──▶ 데이터 품질 ──▶ 예측(P) ──▶ 최적화(O)
                  ▲                              │
                  └──── 시뮬레이션(S)이 투자 근거를 보여 준다 ┘
```

- *"AI 도입 순서는 모델이 아니라 데이터 흐름입니다. 자동화로 품질을 만들고, 그 위에서 예측하고, 시뮬레이션으로 투자를 설득하고, 최적화로 실행합니다."*
- 과제 질문: *"여러분 조직의 CRM은 자동화 몇 % 수준입니까? 그렇다면 지금 이탈 고객 몇 곳을 놓치고 있을까요?"*

## 5. 문제 대응

| 상황 | 원인 | 대응 |
|---|---|---|
| 가람제약이 처음부터 '고' | 이전 리허설 데이터가 남음 | 데이터 운영 → 데모 데이터 초기화 |
| 2막에서 61점이 아니라 '중' 유지 | 미팅일을 과거로 넣었거나, 경쟁사·불만·반응 필드를 지움 | 근거 보기에서 경쟁사 2회·불만 2건 확인. 미팅 노트를 다시 입력 |
| 실제 Claude 모드에서 필드가 다르게 추출됨 | 생성형 AI의 표현 차이 | 확정 전에 경쟁사=베타바이오텍, 불만, 반응=부정을 사람이 확인·수정 → "사람이 확정한다"를 보여 주는 장면으로 활용 |
| 데이터 품질 수치가 슬라이드와 다름 | KAM 창은 담당 고객만 계산 | 관리자 창에서 본다(시작 시 83·82·66·79·92·97%). KAM 창은 84·82·69·83·93·92% |
| 미팅 노트 저장이 안 됨 | 미팅일 칸이 처음에 비어 있음 | 달력에서 오늘 날짜 선택 |
| 오늘의 브리핑이 비어 있음 | 시드 이후 날짜가 바뀜 | `npm run setup` 다시 실행 |
| 신호 수집 버튼이 비활성 | 이미 수집함 | 초기화 후 다시 진행, 또는 브리핑으로 바로 이동 |
| 서버가 `RemoveEnvironmentCleanupHook`로 종료 | Node.js 24.19~24.21 결함 | 최신 `lib/db.ts` 사용, Node 22 LTS 또는 24.22 이상 |

## 6. 리허설 근거

`scripts` 없이 재현하려면 위 대본을 그대로 따라 하면 된다. 2026-11-09 리허설 실측(모의 AI 모드):

- 시드 직후 가람제약: 56점 '중' / 추천 1순위 '비교 기술자료 전달'
- 미팅 노트 확정 후: **61점 '고'** (경쟁사 2회 +13.3, 불만·부정 2건 +15, 주문 감소 +23, 위협 신호 +10, 접촉 공백 +0) / 추천 1순위 **'경영진 리뷰 미팅·장기 공급계약 제안'**
- 고객명 통합('가람제약사')은 위협 신호가 이미 최대(2건)라 점수는 그대로이고, 일관성 지표만 오른다 → 1막에서 품질 장면으로만 사용
- 실험실 결과는 기준일과 무관하게 동일(시드 42)
