## 0. Executive Summary

강의에서 "**자동화(A-1·A-2·A-5)가 CRM 데이터 품질을 높이고, 그 품질이 예측(P-2 이탈위험)과 최적화(O-2 다음 행동 추천)의 성패를 좌우한다**"는 명제를 수치로 시연하는 로컬 웹앱을 만든다. 가상의 다국적 생명과학 기업 한국법인 영업·마케팅 조직을 무대로, 합성 데이터와 공공데이터 형식의 샘플 피드를 SQLite에 담아 `localhost`에서 실행한다.

### Context Anchor

| 축 | 내용 |
|---|---|
| WHY | 마켓 센싱 AI의 가치는 모델보다 데이터 품질에서 결정된다는 점을 수강생이 직접 눈으로 확인하게 한다 |
| WHO | 강사(관리자 역할로 시연), 수강생(KAM 역할로 실습) |

| SUCCESS | 품질-성과 실험실에서 자동화 비율을 올릴수록 종합 품질과 이탈 탐지 재현율이 함께 오르는 결과가 재현된다 (SC-034) |
| SCOPE | A-1·A-2·A-5 → 데이터 품질 계층 → P-2·O-2, 그리고 품질-성과 실험실. 시뮬레이션(S)·실데이터 연동 제외 |

## 1. 개요

- 서비스 이름: **Sensing CRM** (부제: 제약·바이오 마켓 센싱 CRM · 교육용 데모)
- 형태: 데스크톱 우선 반응형 웹앱, `http://localhost:3000`
- 사용 맥락: 대학원·기업 AI 리더십 강의에서 강사가 프로젝터로 시연하고 수강생이 각자 노트북에서 실행

### 5.4 인증

- **인증 사용: 예** — 관리자 전용 기능(수집 실행·초기화·통합 승인·실험)과 담당 범위 데이터 분리가 있다.
- 방식: 이메일·비밀번호, 서버 세션 쿠키(httpOnly, SameSite=Lax), 유효 8시간.
- 결과: 성공 → SCR-002. 실패 → SCR-001-EL-04. 만료 → SCR-001 + SCR-001-EL-06. 권한 없음 → SCR-012. 로그아웃 → 세션 삭제 후 SCR-001.
- 비로그인 사용자가 보호 경로 접근 시 `/login?next={경로}`로 이동하고 로그인 후 원래 경로로 복귀한다(단, 권한이 없으면 SCR-012).

## 15. bkit 실행 계약

- 계약 버전: [확정] 작성·구현 환경에 bkit이 설치되어 있지 않다. 같은 PDCA 절차와 bkit 산출물 경로(`docs/01-plan/features/{feature}.plan.md`, `docs/02-design/features/{feature}.design.md`, `docs/03-analysis/{feature}.analysis.md`, `docs/04-report/features/{feature}.report.md`)로 수동 수행한다. gap 분석은 `npm run gap -- {feature}`(설계 항목 대비 구현 일치율)로 계산한다. bkit 설치 후에는 로컬 계약을 우선한다.
- 설정: `matchRateThreshold` **95** [확정] — 사용자 지시(2026-11-09)
- 명령 순서(feature마다, 14장 순서): `/pdca plan {feature}` → `/pdca design {feature}` → `/pdca do {feature}` → `/pdca analyze {feature}` → (미달 시 `/pdca iterate {feature}`) → `/pdca report {feature}`
- 첫 명령: `/pdca plan foundation-auth`
- 완료 조건(두 관문):
  1. gap 분석 match rate 95% 이상
  2. Check 단계에서 `npm run test`와 `npm run test:e2e`를 **실제로 실행**해 해당 feature SC가 모두 통과하고, 결과를 analysis 문서에 기록
- gap-detector는 설계와 코드를 비교할 뿐 테스트를 실행하지 않으므로 match rate만으로 완료를 판정하지 않는다.
